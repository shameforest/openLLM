- OpenCode 1.19 config (from source, conf ~90, loads fine): `~/.config/opencode/opencode.json` + project root; `$schema=https://opencode.ai/config.json`; model `provider/model`. **Trap: `limit.context`/`limit.output` default 0 -> set both; `temperature` defaults false -> set `true`.** Instructions `AGENTS.md` (CLAUDE.md only fallback). Agents `agents/*.md`, commands `commands/*.md` (`$ARGUMENTS`, `!` shell, `@` files). Permissions: key `permission`, allow/ask/deny, per tool + bash pattern, last match wins (`*` first). Built-in `plan`/`build` agents (Tab); approval gate `OPENCODE_EXPERIMENTAL_PLAN_MODE=1`. Ollama `/v1` can't set context -> env `OLLAMA_CONTEXT_LENGTH=65536`. Current: `bash:{"*":"ask",…}` + long allow list (PowerShell read/create, ollama list/show, dotnet, yarn …), delete/shutdown `deny`, **`task:"deny"`** (sub-agents fail with the local 27B).
- Skills (verified): load UNCHANGED from `.claude/skills/<name>/SKILL.md` (project walk-up and `~`) and `~/.config/opencode/skills/<name>/SKILL.md`; model calls tool `skill({name})`; the companion writes uploads; `/slug …` expands to "Verwende den Skill …" (`expandSkillCommand`; the name in the prompt is the reliable trigger).
- Architecture (honest): the background agent is the LOCAL model, NOT Claude Code; Claude enters only via paid automatic modes (manual copy/paste removed on user request): **Offload** (the LOCAL agent marks self-contained benign sub-tasks `<<<CLAUDE … >>>`, so it decides what leaves; NOT a way to hide a disallowed task from Claude, sensitive work stays local), **Audit** (Opus/Sonnet reviews every local answer, deterministic), **Autopilot** (`AUTOPILOT_PREFIX` -> skill `batch-autopilot`). Needs a stored Claude API key (one-time user action); without key a yellow hint, no cost. Switches in `Modi.tsx` (originally default OFF); `autoAllow` default ON. Folder access = working directory of the local agent. Big multi-file refactors stay with Claude Code.
- UI: main window = only the final answer; thinking, tool steps, handovers in right sidebar `ThinkingSidebar.tsx` (`settings.thinkingOpen`, default closed). Folder choice = in-app browser. Companion restarts at EVERY `start.ps1` run (after an app update restart).
- **One model list: `config/models.json`** (UI, companion, installer read it; `opencode.json` must have the same ids). OpenCode `"autoupdate": false`, `"share": "disabled"`; installer + launcher validate the config with `opencode models ollama` and roll back; `start.ps1` restarts OpenCode when the config is newer or the launch signature changed (not while busy). **Config propagation (OD-72):** `start.ps1` calls `scripts/sync-config.ps1` on every launch, which copies the repo `config/opencode.json` to the installed `~/.config/opencode/opencode.json` (TEXT-ONLY — PS 5.1 `ConvertFrom-Json` rejects the case-only-different bash keys; hash-gated so it only rewrites + restarts OpenCode on a real change; validates + rolls back). Before this, a repo config change (e.g. image support) only reached OpenCode via a full `install.ps1` re-run — a desktop-icon restart kept the stale config. The Claude key is NOT kept in opencode.json (it lives in `~/.opendante/claude-key.json`; sync drops any stray anthropic block). Env `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS/EXTERNAL_SKILLS=1`: the user's `~/.claude` skills no longer reach the local model (fixed prompt 17.6k → 9.5k tokens, −46 %, measured via capture proxy).
- **Plan mode:** plan agent may edit only `*opencode\plans\*.md`; never set `external_directory` or a plain `edit: deny` there (overrides OpenCode's built-in plan exception, last match wins; verified via `GET /agent`). In a git folder plans land in `<project>/.opencode/plans/` (hidden from the changes list).
- **Undo/changes need git:** OpenCode snapshots only git folders (non-git folder = project `global`, empty diff; same edit after `git init` → diff). UI hint "Sicherung einschalten" → `POST /project/git/init`.
- **Thinking / effort (OD-16/OD-29/OD-74, measured):** variant `ohne-denken` = `reasoningEffort: none` → Ollama `reasoning_effort: none` turns thinking off (1 s vs 10 s, but a wrong answer on a counting question); for the uncensored weights `low`/`think:false` have no effect (ollama show: levels false/true). **OD-74:** `settings.thinkMode` became `settings.effort` — a model-aware effort level (from `config/models.json` `effort[]`, each mapped to an `opencode.json` variant) shown under the prompt box next to the model select. Uncensored/abliterated → 2 real levels (Schnell=none, Gründlich=on); original `qwen3.8:27b` → 4 (Schnell/Niedrig/Mittel/Hoch = none/low/medium/xhigh, ollama show declares them). Plan mode always thinks. none-vs-on measured (12/12 74 min vs 11/12 167 min); the graded steps are model-declared, outcome not yet Testlauf-ranked.
- **Claude modes:** default model Sonnet 5.5 for fresh setups, daily cap (`claudeDailyUsd`, default 2 $) enforced in the companion (`~/.opendante/claude-usage.json`, `GET /claude/usage`). Companion accepts only its own origins (403 otherwise) and JSON POSTs (415). **Claude-Hilfe = two sliders (OD-64):** `offloadShare` (MAX) caps opportunistic offload of benign subtasks; `offloadMin` (MIN) is a floor — if Claude's share stayed below it, `claudeImprove` has Claude improve the finished answer once (post-turn, client-side, not mirrored to the companion; same key/cap path as the audit). MIN ≤ MAX enforced. Rationale: the local 27B rarely offloads on its own, so MIN guarantees some Claude value.
- **Claude-Hilfe regelbasiert (OD-75):** `settings.autoClaude` (default off) + a checkbox under the sliders. Because the local 27B does not self-offload (so the MAX share never fills), OpenDante decides AT TURN END from OBSERVABLE signals instead of a token share: the finished answer admits a struggle (`fehlgeschlagen`/`konnte … nicht`/`schlägt fehl`/…) → `claudeImprove` (fix); a risky area in the prompt OR the diff (delete, money, permissions, regex, timezone, leap year) OR a large change (>3 files / >150 lines) → `claudeAudit` (review). Pure testable `autoClaudeTrigger`+`AutoSignals` (`web/src/claude.ts`, +5 vitest); wired in `App.tsx postProcessClaude` (re-reads the per-message diffs), obeys the Claude key + daily cap. NOT yet live-tested with a real model (GPU busy); logic unit-tested only. The MAX/MIN sliders stay as they were.

- **Auto-allow (`requests.ts`):** asks for anything outside the working folder (except OpenCode's data dir), for push/reset/clean/delete aliases/`reg`/download-and-run and interpreter one-liners (`python -c`, `node -e`, `powershell -Command`, `cmd /c`); starting installed programs (`C:\Program Files\…\python.exe`) does not count as outside. - **Voll-Automatik (OD-71, per run):** a "⚡ Voll-Automatik" button arms a stronger-than-autoAllow mode for ONE prompt: `fullAutoDecision` grants every permission (`once`), questions are auto-rejected (agent decides), only doom-loops still get redirected. - **Projektordner (OD-73):** a project = a working folder (`modes.workdir`). Its parts live in the folder's gitignored `.opendante/`: `projekt.json` (name/description), `projektnotiz.md` (instructions, OD-41), `wissen/` (knowledge items + a `.rag.json` embeddings index). The Verlauf groups by project (`groupChats`); the ProjectPanel ("+" menu) manages name/instructions/knowledge with a capacity bar. "Remove project" only untracks the folder — code, chats and knowledge stay on disk. v1 knowledge is text-only.

## OpenCode server API (verified)
- `opencode serve` -> http://127.0.0.1:4096, no auth on localhost, CORS open to localhost:*. `GET /global/health`; spec of the running instance `GET /doc`.
- `POST /session {title}` (a title skips the hidden title LLM call) -> `{id}`. `POST /session/{id}/prompt_async` `{agent, model:{providerID:"ollama", modelID:"qwen3.8:27b"}, parts:[{type:"text",text}]}` -> 204. `POST /session/{id}/abort`. Slash model names (`ollama/orcarouter/…`) resolve (`opencode models ollama` lists all three); a not-loaded model -> clean 404 from Ollama.
- Folder PER REQUEST via query `directory` (or header `x-opencode-directory`), no restart (source tag v1.19.0: workspace-routing.ts, groups/session.ts:203-206/330-335; conf 90). `/event` IS folder-bound (groups/event.ts:14-20, handlers/event.ts:35-38; conf 90): a stream without `directory` does NOT see a folder session, so the stream carries the folder and reconnects on change. Sessions persist (`~/.local/share/opencode/opencode.db`); `GET /session?directory=` lists them.
- SSE `GET /event`: `message.part.delta {field, delta}`; `message.part.updated {part:{type:"tool", state:{status}}}`; `message.updated {info.tokens}`; `session.idle` / `session.status{type:"idle"}` end the turn; `session.error` (text at `error.data.message`).
- **Measured:** a `reasoning` part carries deltas with `field:"text"` (not `"reasoning"`) -> track part type per `partID` from `message.part.updated` (Ollama itself separates `delta.reasoning`/`delta.content`). Tokens are EXACT via `message.updated info.tokens` (no `includeUsage`); `output` already includes thinking (`reasoning` = 0); read = `input + cache.read + cache.write` (seen input 4 + cache.read 16,373).
- **Step order (measured):** each step = own assistant message, starts with `message.updated` of a NEW assistant id (= prefill), `step-start` only with the first output, tool inside the step (pending->running->completed), `step-finish` closes. Tool arguments (file content) are NOT streamed as text -> char-based speed useless for estimates.
- Permissions/questions (checked vs `GET /doc`): `permission.asked` -> `POST /permission/{id}/reply` (`once|always|reject` + message); `question.asked`, `*.replied`, `*.rejected`; open ones via `GET /permission`, `GET /question`; reply/reject question.
- Undo/changes/plan/context (checked vs `GET /doc`, used in the UI): `GET /session/{id}/diff?messageID=<user msg>` (per user message; plan mode's switch to build adds a second user message in the same turn), `POST …/revert {messageID}`, `POST …/unrevert`, `GET …/todo` + event `todo.updated`, `POST …/summarize {providerID, modelID}`, `GET /path` (home/state/config/directory), `GET /agent` (effective permission rules), `GET /project/current` (`vcs:"git"` or none), `POST /project/git/init`. `session.status` `{type:"retry", attempt, message, next}` after a model error. Prompt body takes `variant`. Assistant `message.updated` carries `info.agent` (`plan`/`build`).
- Ollama: `GET 127.0.0.1:11434/api/ps` (CORS ok) shows whether the model is loaded; `POST /api/generate {model, keep_alive}` without prompt extends the unload time (UI keeps the model ~60 min warm, only if already loaded); the `task` sub-agent fails with `500 "no user query found in messages"` (routes.go:3251). Measured: prompt reading ~496 tok/s, writing ~21.8 tok/s.
- Anthropic via companion `POST /claude`: `api.anthropic.com/v1/messages`, `x-api-key`, version 2023-06-01; key + model read from `~/.opendante/claude-key.json` (legacy fallback `opencode.json`).
- Companion (own, port 4097, zero-dep Node): `/settings` (global instructions into a replaceable AGENTS.md block; Claude key + model into `~/.opendante/claude-key.json`; an EMPTY key deletes that file), `GET/POST /skills`, `/update/app`, `/update/models` (name regex-checked), `GET /fs?path=`, chats CRUD in `~/.opendante/chats` (`OPENDANTE_DATA` overrides; id regex `^[a-z0-9-]{8,64}$`), `POST /repo/clone {url}` (only https://github.com/…, shallow clone to `~/OpenDante-Projekte/<name>` or `git pull --ff-only`), `GET /repos`, `POST /git {path,action,message}` (no shell; needs .git; commit = add -A + commit -m), `/claude`, `GET /claude/usage`.
