## Fortschrittsanzeige Schritt für Schritt + realistischer Countdown (2026-10-15)
- Nutzer-Report: „Rest: lernt noch“ nach 6 Min., Balken fest. Ursache: alte Schätzung (`eta.ts`) lernte nur aus FERTIGEN Antworten (`openllm.samples`); ohne Verlauf fester 4-%-Balken; außerdem behandelte sie einen mehrstufigen Agent-Auftrag wie eine einzige Antwort.
- **GEMESSEN (Ereignisreihenfolge OpenCode 1.19 + Ollama, Probe `orderprobe`):** Jeder Schritt = eigene Assistant-Nachricht. Schritt beginnt mit `message.updated` einer NEUEN assistant-id (Prefill = Eingabe lesen), `step-start` kommt erst mit der ersten Ausgabe, Werkzeug läuft innerhalb des Schritts (pending→running→completed), `step-finish` schließt ihn. Werkzeug-Argumente (z. B. Dateiinhalt) werden NICHT als Text gestreamt → Zeichen-basierte Geschwindigkeit unbrauchbar für die Schätzung.
- **`progress.ts`** (pure, unit-getestet, Testfälle = gemessene Folge): verfolgt Schritte, lernt pro Schritt `{prefillMs, postMs}` (localStorage `openllm.steps`, 60) und pro Auftrag `{ms, steps}` (`openllm.tasks`, 30). Countdown = 75. Perzentil der gelernten Werte (die meisten Schritte enden innerhalb), vorher Startwerte (`PRIOR`, „(grob)“). Überzogen → kein rückwärts laufender Countdown, sondern „dauert länger als üblich (seit …)“ mit laufendem Streifen. Prefill > 30 s (= Modell-Laden) wird nicht gelernt. Gesamtschätzung erst ab 3 Aufträgen: „Gesamt ~m:ss · typisch N Schritte“, sonst ehrlich „offen“. Anzeige geglättet (`smoothEnd`, ~2,5 s).
- **Anzeige (`Clock` in App.tsx):** „Schritt N · liest den Auftrag ein / denkt nach / schreibt / führt aus: bash · …“, Zeit seit Absenden, Balken pro Schritt, „Schritt N fertig in ~0:09“, Tokens/s (nur bei ≥200 sichtbaren Zeichen), Gesamt. **Modell-Laden** wird per Ollama `GET 127.0.0.1:11434/api/ps` (CORS erlaubt, alle 2 s) erkannt → „lädt das Modell in die Grafikkarte… · dauert etwa 1 Min.“; danach „liest alles einmal komplett ein“ (erstes Prefill nach dem Laden ohne Cache, gemessen ~25 s).
- **BEWIESEN** (Shadow-PC, Test-Server 4196/4197, zensurfreies Modell): Lauf 1 nach `ollama stop`: Laden ~10 s angezeigt, Prefill 37 s, dann Countdown 0:18→0:13, Schritte 2+3; Antwort „Banane“ korrekt. ## Warum komplexe Aufträge früh feststeckten — Ursachen + Behebung (2026-10-15)
- **Analyse an echten Sitzungen** (OpenCode-DB `~/.local/share/opencode/opencode.db`, read-only Python): die festgefahrenen Turns endeten bei `tool:bash[running]` (out=0/in=0, finish=None) oder `tool:question[error]`. Dazu Ollama-Log: `500 "no user query found in messages"` (routes.go:3251), mehrfach wiederholt.
- **Ursache A (Hauptgrund): die Web-Oberfläche beantwortete Erlaubnis-Anfragen nicht.** `opencode.json` hat `bash:{"*":"ask",…}`. Jeder Befehl außerhalb der Erlaubt-Liste (z. B. `Get-ChildItem -Recurse`, `New-Item`, `mkdir`) löst ein `permission.asked`-Ereignis aus. `reduceEvent`/`App.tsx` hörten darauf NICHT und hatten keinen Antwortweg → der Turn hing für immer bei `bash running`, Status blieb `busy` („läuft…"). **Reproduziert** (Test-Server, `runprompt.mjs`): nach 7 s `PERMISSION bash` und dann Stillstand.
- **Ursache B: das `question`-Werkzeug blockierte** (Modell stellt Multiple-Choice-Frage, UI konnte sie nicht zeigen/beantworten → Nutzer brach ab).
- **Ursache C: `task`-Werkzeug (Hilfs-Agent)** scheiterte mit „no user query"/„Subagent failed" und blockierte die Sitzung (lokales 27B + Subagent über Ollama).
- **Behebung:**
  1. **API** (`api.ts`, gegen `GET /doc` der laufenden Instanz verifiziert): `listPermissions`/`listQuestions`/`replyPermission(once|always|reject,+message)`/`replyQuestion`/`rejectQuestion`/`sessionStatus`/`sessionMessages`.
  2. **UI** (`App.tsx` + `RequestCard.tsx`): hört auf `permission.asked`/`question.asked`/`*.replied`/`*.rejected`, zeigt eine Karte über dem Eingabefeld (genauer Befehl/Datei/Ordner/Frage, Knöpfe Einmal/Immer/Ablehnen bzw. Antwortoptionen + Freitext). Bei (Neu-)Verbindung UND alle 8 s werden offene Anfragen per `GET /permission` + `/question` nachgeholt (Reload/Aussetzer verliert keine). Die Clock zeigt „wartet auf deine Antwort" statt endlos „läuft…", Countdown pausiert.
  3. **Automatik „Befehle automatisch erlauben"** (`requests.ts`, neuer Modus `autoAllow`, **Standard AN**): harmlose Anfragen → automatisch „once"; `doom_loop` (Agent dreht sich dreimal im Kreis) → `reject` mit Umlenk-Hinweis (`LOOP_HINT`); riskantes (`git push`, reset --hard, clean, rm/del/Remove-Item/format/shutdown) bleibt beim Nutzer (`RISKY`-Regex). Unit-getestet.
  4. **opencode.json**: Erlaubt-Liste stark erweitert (gängige PowerShell-Lese/Erstell-Befehle: Get-ChildItem/Content, Test-Path, Select-*, New-Item, mkdir, ollama list/show, dotnet, yarn …); Löschen/Herunterfahren bleibt `deny`; **`task:"deny"`** (keine Subagenten für das lokale Modell).
- **BEWIESEN (Shadow-PC, Test-Server + Logging-Proxy, zensurfreies Modell, NEUER Build):** (a) autoAllow AUS: Befehl ausgelöst → Karte mit genauem Befehl + „Schritt 1 wartet auf deine Antwort", „Einmal erlauben" → zweite Anfrage → erlaubt → Auftrag fertig mit Dateiliste. (b) autoAllow AN: Auftrag „Ordner demo anlegen, Datei anlegen, auflisten" lief OHNE jede Karte komplett durch; `demo\info.txt` real auf der Platte; sauber idle.
